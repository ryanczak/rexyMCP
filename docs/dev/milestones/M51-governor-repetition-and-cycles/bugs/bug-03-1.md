# Bug 1 on phase-03: `repeat_nudge_silent_when_outputs_differ` varies the command instead of issuing identical calls

**Severity:** major
**Status:** open
**Filed:** 2026-11-24

## What's wrong

In `executor/src/agent/tests.rs:6348-6356`, `repeat_nudge_silent_when_outputs_differ` scripts three **different** commands instead of three identical calls whose outputs differ:

```rust
#[tokio::test]
async fn repeat_nudge_silent_when_outputs_differ() {
    let dir = TempDir::new().unwrap();
    let mk = |i: usize| native("bash", json!({ "command": format!("echo run-{i}") }));
    let client = MockAiClientScript::new(vec![
        vec![mk(1)],
        vec![mk(2)],
        vec![mk(3)],
        vec![token("done")],
    ]);
```

The test passes without ever exercising the output-equality check in `executor/src/agent/mod.rs:1189`.

## What should happen

Per `phase-03-repeat-nudge.md` § Test plan, `repeat_nudge_silent_when_outputs_differ` must test the negative case where **three identical calls** (same tool name and identical arguments on every call) return **different tool outputs** (not merely timing differences) and therefore inject zero nudges. Removing `&& repeat_norm_out.as_deref() == Some(&*repeat_norm)` from `executor/src/agent/mod.rs:1189` must cause this test to fail. The test must remain hermetic (`STANDARDS.md` §3.3 — no host state outside the test's `TempDir`).

## Root cause

Because each scripted call changes the bash command string (`echo run-1`, `echo run-2`, `echo run-3`), `repeat_key.as_ref() == Some(&key)` at `executor/src/agent/mod.rs:1189` already evaluates to `false` on calls 2 and 3, short-circuiting the `&& repeat_norm_out.as_deref() == Some(&*repeat_norm)` comparison. As a result, the output-difference reset invariant is completely untested.
