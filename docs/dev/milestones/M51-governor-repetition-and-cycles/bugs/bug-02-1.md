# Bug 1 on phase-02: Trailing-plumbing regex defects and production `.unwrap()` calls in `normalize.rs`

**Severity:** major
**Status:** open
**Filed:** 2026-11-24

## What's wrong

1. **`TEMP_CAT` misses `&&` (`executor/src/governor/normalize.rs:78`):** the separator
   character class is `[;&]` (a single `;` or `&`), so `cmd > /tmp/x && cat /tmp/x`
   (without a preceding `| tail`) is never stripped. The existing test
   `strips_trailing_tail_head_wc_and_stderr_plumbing` only passed for
   `grep ... | tail -4 > /tmp/x && cat /tmp/x` because `TAIL_PIPE` swallowed
   everything from `| tail` to end-of-line.
2. **`TAIL_PIPE` greedily consumes substantive stages and non-temp redirects
   (`executor/src/governor/normalize.rs:75`):** `r"\s*\|\s*(tail|head|wc|cat)\b.*$"`
   matches `.*$` after `tail|head|wc|cat`, so:
   - `echo foo | cat | grep bar` and `echo foo | cat | grep baz` collapse to the
     same string `echo foo` (stripping the substantive `| grep` stage), and
   - `cargo test | tail -4 > src/a.txt` and `cargo test | tail -4 > src/b.txt`
     collapse to `cargo test` (stripping the non-temp project redirect).
3. **`TEMP_CAT` and `tee` strip non-temp project paths
   (`executor/src/governor/normalize.rs:78, 86-100`):** `echo a > src/x.rs; cat src/x.rs`
   and `cargo test | tee src/a.txt` are stripped even though `src/x.rs` and
   `src/a.txt` are project files, not `/tmp/...` or `$TMPDIR/...` temp paths.
4. **Production `.unwrap()` calls (`executor/src/governor/normalize.rs:59, 61, 75, 80, 82, 84, 93, 97, 125, 126`):**
   `strip_trailing_plumbing` calls `caps.get(0).unwrap()` at lines 93 and 97, and
   the eight `LazyLock<Regex>` initializers use bare `.unwrap()` instead of
   `.expect("...")` with an invariant message (`STANDARDS.md` §1 & §2.1).

## What should happen

Per `phase-02-command-output-normalization.md` § Spec #1 and `STANDARDS.md` §1 & §2.1:
- `> /tmp/<name> && cat /tmp/<name>`, `> /tmp/<name>; cat /tmp/<name>`,
  `> "$TMPDIR/<name>" && cat "$TMPDIR/<name>"`, and `| tee /tmp/<name>` (and
  `$TMPDIR/...`) must strip even when not preceded by `| tail`.
- Trailing `| tail`, `| head`, `| wc`, `| cat` stripping must only remove a
  genuinely trailing stage (nothing containing a later `|`, `&&`, `;`, or `>`
  redirect), so substantive stages (`| grep ...`) and non-temp redirects
  (`> src/a.txt`) are preserved.
- Capture-and-cat and `| tee` stripping must only match temp paths (`/tmp/...`
  or `$TMPDIR/...`), never project paths (`src/...`).
- Zero `.unwrap()` calls in production code in `executor/src/governor/normalize.rs`
  (handle `caps.get(0)` without panicking; use `.expect("...")` explaining the
  compile-time-literal invariant for `LazyLock<Regex>`).

## Root cause

- `TEMP_CAT` at `executor/src/governor/normalize.rs:78` uses `[;&]` instead of
  matching `&&` or `;`, and accepts any non-whitespace path instead of restricting
  to `/tmp/` or `$TMPDIR/` paths.
- `TAIL_PIPE` at `executor/src/governor/normalize.rs:75` ends with unbounded `.*$`,
  which swallows subsequent pipeline stages and redirects and masked the `&&` bug
  during testing.
- `strip_trailing_plumbing` unwraps `caps.get(0)` at lines 93 and 97 and the
  `LazyLock` regexes use bare `.unwrap()`.
